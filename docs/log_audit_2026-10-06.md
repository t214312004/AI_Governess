## 已確認並修補的 bug

**文字輸入啟用語音輸出時，log 錯標輸入模式並重複記錄開始事件。**

當天 17:55、17:59、18:21、18:23、18:24 的五次文字請求，都先由 `send_text_message()` 寫出 `mode=text`，接著又由共用朗讀流程寫出相同 request 的 `mode=voice`。LLM I/O、first-token、完成與失敗紀錄也使用錯誤模式。每個輸入實際只發出一次 Codex `turn/start`，但 `llm.request_started` 的筆數變成兩倍，會使請求統計與故障追查失準。

根因在 `core/assistant.py`：`_execute_text_llm_request()` 為了朗讀回覆呼叫 `_execute_llm_request()`，後者把輸入模式寫死為 `voice`。

修補讓共用流程接受 `input_mode`；文字輸入傳入 `text`，所有相關事件、LLM I/O 與 failure 分類維持相同模式，開始事件只保留一次。語音輸入仍使用 `voice`，文字輸入的朗讀仍使用原有 TTS pipeline。

新增 regression tests 覆蓋文字輸入開啟／關閉朗讀，以及 backend exception。修補前成功重現兩個 failure；修補後通過，也同步更新既有 session integration test 的參數契約。

## 補強 warning 診斷

`llm/codex_cli_client.py` 的 `codex.stderr` 現在增加：

- `category`：依固定關鍵字分為 telemetry、authentication、rate_limit、transport 或 unknown。這是診斷提示，不能當成已確認的根因。
- `fingerprint`：移除時間戳與 ANSI 顏色後產生的 SHA-256 摘要前 12 碼，用來比較是否重複訊息。
- `turn_active`：warning 發生時是否有進行中的 turn。

上述欄位不記錄原始 stderr 本文；測試確認 private payload 不會出現在 log 參數。這是追查能力的補強，沒有宣稱已修復今天三個 warning 的未知原因，也沒有重寫歷史 log。
